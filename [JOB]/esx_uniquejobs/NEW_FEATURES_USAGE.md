# راهنمای استفاده -- فیچرهای جدید DOJ/LAW

نصب لازم نداره، فقط ریسورس رو ری‌استارت کنید (جدول‌ها خودکار ساخته می‌شن --
جزئیات در `NEW_FEATURES_CHANGELOG.md`).

## `/doj` (marshal / judge / cia / cid / fbi / doa)

- **Sabeghe-ye Kayfari (Rap Sheet)** -- با وارد کردن ID یا اسم: دستگیری/اتهام
  (`criminal_records`) + Booking-e CAD (`doj_criminal_records`) + جریمه‌ی
  پرداخت‌نشده + آخرین مکان شناخته‌شده + مشخصات ظاهری (جنسیت/تاریخ تولد/قد) +
  آخرین Mugshot ثبت‌شده (اگه باشه، به‌صورت thumbnail + گزینه‌ی دیدن در سایز
  بزرگ) + یک گزینه‌ی «Namayesh-e Motn-e Kamel (Copy)» برای گرفتن نسخه‌ی متنی
  کامل و کپی‌شدنی. همین Rap Sheet دقیقاً زیر `/law` هم (از منوی Mugshot) در
  دسترسه -- یک منبع واحد، نه دو کارت شناسایی جدا.
- **تقویم دادگاه (Court Docket)** -- از منوی اصلی: لیست همه‌ی جلسات. از داخل
  جزئیات هر پرونده هم می‌تونید «Zamanbandi Jalase-ye Dadgah» بزنید (بر حسب
  چند دقیقه‌ی دیگر). فقط **judge** می‌تواند حکم نهایی (Guilty / Not Guilty /
  Plea Deal) ثبت کند -- با ثبت حکم، پرونده به‌طور خودکار Closed می‌شود.
- **Timeline پرونده** -- داخل جزئیات هر پرونده، یک نمای زمانی یکپارچه از
  تمام مدارک/یادداشت‌ها/اتهامات/تغییرات وضعیت/جلسات دادگاه/انتقال مدارک.
- **زنجیره‌ی نگهداری مدارک (Chain of Custody)** -- داخل جزئیات هر پرونده،
  «Zanjire-ye Negahdari-ye Madarek»: لیست تمام مدارک آن پرونده؛ با انتخاب هر
  کدام، کل زنجیره‌ی تحویل (از جمع‌آوری اولیه تا هر انتقال بین
  افسران/دپارتمان‌ها) با زمان دیده می‌شود، و «Enteghal-e Madrak» یک انتقال
  جدید (گیرنده + دپارتمان + دلیل) ثبت می‌کند. هر انتقال خودکار در Timeline
  پرونده هم ثبت می‌شود.
- **داشبورد آماری** -- جرایم بر اساس نوع (Top 10)، روند بازداشت ۱۴ روز
  اخیر، فعال‌ترین افسران -- نمودار میله‌ای متنی داخل همان منو.
- **بازبینی عملکرد افسر** -- با وارد کردن ID یا اسم افسر: تعداد
  بازداشت/اتهام، رتبه در Leaderboard، و سابقه‌ی گزارش‌های Internal Affairs
  (از جدول `doj_ia_reports` که ماژول CAD مدیریتش می‌کند).

## `/law` (police / sheriff / mt)

- **ثبت توقف (Traffic Stop)** -- ثبت سریع یک توقف ترافیکی (دلیل + نتیجه:
  اخطار/جریمه/بازرسی/ارجاع به دستگیری) بدون نیاز به Booking کامل، به‌علاوه
  تاریخچه‌ی توقف‌های ثبت‌شده. مکان توقف (نام خیابان) خودکار از موقعیت افسر
  گرفته و ذخیره می‌شود. وارد کردن پلاک (اختیاری) خودکار پلاک رو با
  BOLO های فعال CAD چک می‌کند و در صورت Hit یک هشدار صوتی + پنجره نشون
  می‌ده. دو گزینه‌ی جدا هم هست: «Barresi Pelak (BOLO)» برای چک سریع بدون
  ثبت تعقیب، و «BOLO-haye Active» برای دیدن فهرست کامل BOLO های فعلی.
- **Baz Kardan CAD (MDT)** -- میان‌بر مستقیم به پنل `/cad`.
- **Mugshot** *(بازسازی‌شده -- نسخه‌ی قبلی این ویژگی هیچ‌وقت واقعاً کار
  نمی‌کرد، فایل‌هاش روی دیسک نبودن)* -- با وارد کردن ID/اسم شهروند، سه گزینه:
  - **Gereftan Aks Jadid** -- اگه شهروند همون لحظه آنلاین باشه، یک دوربین
    واقعی مستقیم روی صورتش zoom می‌کنه (هر دو نفر برای چند لحظه فریز
    می‌شن، یک صدای شاتر پخش می‌شه)، و بعد:
    - **پیش‌فرض (بدون هیچ تنظیمی)**: عکس همون‌جا گرفته و مستقیم به‌صورت
      base64 توی خود دیتابیس (`dept_mugshots.photo_url`, ستون
      `MEDIUMTEXT`) ذخیره می‌شه -- بدون نیاز به هیچ سرور/هاست بیرونی،
      یعنی چیزی نیست که fetch/آپلودش fail بشه.
    - اگه بخوای به‌جاش از یک هاست عکس بیرونی استفاده کنی، کافیه convar
      `mugshot_upload_url` رو ست کنی (و اختیاری `mugshot_upload_field`
      برای اسم فیلد فرم آپلود، پیش‌فرض `files[]`).
    - اگه شهروند آنلاین نباشه یا ریسورس `screenshot-basic` نصب نباشه، یک
      URL عکس به‌صورت دستی گرفته می‌شه.
    - هر عکس (چه base64 چه URL) یک ردیف جدید در `dept_mugshots` ذخیره
      می‌شه -- یعنی تاریخچه‌ی کامل، نه یک عکس آخر که هربار overwrite بشه.
    - **تنظیم دوربین (اختیاری)**: با convar های `mugshot_cam_distance`
      (فاصله، پیش‌فرض `0.55`)، `mugshot_cam_fov` (زوم، پیش‌فرض `30.0`، هرچی
      کمتر زوم بیشتر) و `mugshot_cam_height` (ارتفاع سر، پیش‌فرض `0.62`)
      می‌تونی کادر عکس رو بدون تغییر کد جا‌به‌جا کنی.
  - **Tarikhche-ye Aks-ha** -- فهرست تمام عکس‌های قبلی این شهروند، هرکدوم
    با thumbnail واقعی (نه فقط اسم فایل) + سابت‌کننده + چند دقیقه پیش.
  - **Rap Sheet + Aks** -- میان‌بر مستقیم به همون Rap Sheet مشترک با
    `/doj` (بالا) -- که الان آخرین Mugshot رو هم توش می‌بینید.

## نکات فنی

- تمام کد با همان الگوی خود ریسورس نوشته شده: ESX + `ox_lib` context menu +
  `oxmysql` (`MySQL.Async`/`MySQL.Sync`)، همون سبک نام‌گذاری Finglish.
- هیچ فایل اصلی (`doj_cases.lua`, `records_manager.lua`, ...) دست نخورده؛
  Timeline و زنجیره‌ی مدارک با یک هندلر دومِ همان event های موجود کار
  می‌کنند (FiveM هر هندلری که برای یک event ثبت بشه رو اجرا می‌کنه).
  استثنا: `records_manager.lua` خودش مستقیم ویرایش شد تا Rap Sheet هم
  مشخصات ظاهری (`users`) و هم آخرین Mugshot (`dept_mugshots`) رو برگردونه
  -- این دو تا داده‌ی خالص هستن، هیچ منطق قبلی تغییر نکرده.
- **Mugshot Convars (همه اختیاری، توی `server.cfg`):**
  - `mugshot_upload_url` -- خالی = ذخیره‌ی base64 مستقیم توی دیتابیس
    (پیش‌فرض و توصیه‌شده تا وقتی یک هاست عکس واقعی نداری). پر شده = عکس
    خودکار به این آدرس آپلود می‌شه.
  - `mugshot_upload_field` -- اسم فیلد multipart که سرور آپلود شما (فقط
    وقتی `mugshot_upload_url` پر باشه) انتظار داره (پیش‌فرض `files[]`).
  - `mugshot_cam_distance` / `mugshot_cam_fov` / `mugshot_cam_height` --
    تنظیم فاصله/زوم/ارتفاع دوربین مقابل صورت.
  - **نیاز اجباری**: ریسورس `screenshot-basic` باید نصب و قبل از
    `esx_uniquejobs` استارت شده باشه، وگرنه سیستم مستقیم می‌ره سراغ گرفتن
    URL دستی.
- اگه سرورت از قبل با نسخه‌ی خیلی اول این فیچر (ستون `photo_url` به‌صورت
  `VARCHAR(500)`) ری‌استارت شده، دفعه‌ی بعد که استارت بشه، `db_migrations.lua`
  خودش ستون رو به `MEDIUMTEXT` عریض می‌کنه (بدون از دست رفتن داده).
- همه‌ی فایل‌های Lua با `luac5.4 -p` سینتکس‌چک شده‌اند.
