# Unique_inventory

ادغامِ `esx_inventory` + `esx_inventoryhud` + `esx_inventoryhud_trunk` در یک ریسورس، با رفع باگ‌های زیر.

## نصب
1. این پوشه رو با اسم `Unique_inventory` بذار توی `resources/`.
2. `esx_inventory`, `esx_inventoryhud`, `esx_inventoryhud_trunk` قدیمی رو از `server.cfg` **پاک کن** (هر سه‌تا الان همینجان).
3. `install.sql` رو (اگه قبلاً جدول‌های ترانک رو نداشتی) روی دیتابیس اجرا کن.
4. `ensure Unique_inventory` رو به `server.cfg` اضافه کن — **بعد از** `essentialmode` و `oxmysql`، و بعد از `Unique_AdminPanel` (چون کارت هویت از `esx_aduty:checkAdmin` استفاده می‌کنه).

## باگ‌های رفع‌شده

### ۱) کال‌بک‌های سرور اصلاً کار نمی‌کردن (ریشه‌ای)
هر سه ریسورس قدیمی با `ESX.RegisterServerCallback` روی یه کپیِ محلیِ ESX (از `esx:getSharedObject`) کال‌بک ثبت می‌کردن. چون این سرور `essentialmode` هست نه `es_extended`، این کپی جدولِ زنده‌ی سرور نیست و هر کدوم بی‌صدا شکست می‌خوردن — دقیقاً همون باگی که خودِ `Unique_AdminPanel` قبلاً پیدا کرده بود. همه‌شون الان از `server/callback_bridge.lua` (همون الگوی export-relay خودِ essentialmode) رد می‌شن. این شامل می‌شد:
- `Parzival:getHouseINV` / `getGangINV` / `getJobINV1` / `getJobINV2`
- `esx_inventoryhud:GetData` / `getPlayerInventory` / `getPlayerInventory1` / `getPlayerInventory2323` / `GetHouseItems` / `updateCraft` / `calculateCraft`
- `esx_trunk:getInventoryV` و بقیه‌ی کال‌بک‌های صندوق‌عقب

### ۲) وزن اینونتوری کلاً فیک بود
سرور وزن هر آیتم/اسلحه رو هارد-کد `10` می‌فرست (بدون توجه به آیتم واقعی)، و کلاینت هم `1000.0/4000.0` رو ثابت نشون می‌داد — دقیقاً همون عددی که توی اسکرین‌شات دیده می‌شه، مهم نیست چی توی اینونتوریته. الان وزن واقعی از `ESX.getItemWeight`/`ESX.getWeaponWeight` محاسبه می‌شه و مجموع واقعی برمی‌گرده. سقف وزن قابل تنظیمه: `HudConfig.MaxInventoryWeight` (پیش‌فرض ۹۰).

### ۳) کارت هویت
- ردیف Admin هیچ‌وقت `admin` رو از سرور نمی‌گرفت، پس همیشه (برای همه) نمایش داده می‌شد (fail-open). الان:
  - از همون معیاری که خودِ AdminPanel استفاده می‌کنه (`esx_aduty:checkAdmin` → `xPlayer.permission_level > 1`) میاد، نه یه حد نصاب اختراعی.
  - به‌صورت پیش‌فرض مخفیه (`display:none`) تا وقتی سرور تأیید کنه — یعنی fail-closed.
  - اگه `esx_aduty` بالا نباشه، بعد از ۲ ثانیه timeout میخوره و کارت هنگ نمی‌کنه.
- متن‌های استاتیکِ Placeholder توی HTML به پرتغالی بودن (`Passaporte`, `Telefone`, ...) در حالی که خودِ `app.js` (قبلاً به اسم گمراه‌کننده‌ی `jquery.js`) داشت درست از `config.js` (انگلیسی) استفاده می‌کرد. حالا Placeholder هم با همون لیبل‌های `config.js` هماهنگه.

### ۴) مسیر آیکن‌ها
- ۷ تا از ۸ محل `SendNUIMessage` به‌درستی به `esx_inventoryhud/html/img/items/` اشاره می‌کردن (یه وابستگی بین‌ریسورسی که فقط چون هر دو با هم اجرا می‌شدن کار می‌کرد).
- یه مورد (اینونتوری صندوق خونه/Cargo) به یه ریسورس ناموجود به اسم `inventory` اشاره می‌کرد — آیکن‌هاش هیچ‌وقت لود نمی‌شدن.
- الان هر ۸ مورد یکسان به `nui://Unique_inventory/html/img/items/` اشاره می‌کنن (همون ۴۴۲ تا آیکن که از esx_inventoryhud اومدن).

### ۵) فایل واقعیِ اپ گمراه‌کننده بود
`nui/jquery.js` جیکوئری واقعی نبود — کل منطق اینونتوری (۱۷۰۰+ خط) بود، با ۲۵ تا آدرس NUI هارد-کد به `http://esx_inventory/...`. با تغییر اسم ریسورس این‌ها می‌شکستن. اسمش شد `app.js` و همه‌ی آدرس‌ها اصلاح شدن به `Unique_inventory`.

### ۶) تداخل بین فایل‌ها بعد از ادغام (باگ‌هایی که خودِ من موقع ادغام معرفی می‌کردم، پیدا و رفع شدن قبل از تحویل)
- تابع `openmenuvehicle` توی esx_inventory و trunk هم‌نام بود → یکی دیگری رو بی‌صدا خاموش می‌کرد. اسم نسخه‌ی trunk شد `Trunk_OpenMenuVehicle`.
- هر دو `Config = {}` (هاد و ترانک) روی هم می‌نشستن و فیلدهای همو پاک می‌کردن → جدا شدن به `HudConfig` و `TrunkConfig` و همه‌ی ارجاعات آپدیت شدن.

## ظاهر (تم رنگی)
CSS از قبل دقیقاً همین تم طلایی/مشکیِ UNIQUE بود (`#d4af37` به عنوان رنگ اصلیِ لهجه، پس‌زمینه‌های مشکی/نیمه‌شفاف) — همون چیزی که توی اسکرین‌شاتت هست. نیازی به بازطراحی از صفر نبود؛ فقط باگ‌های واقعی (بالا) که ظاهرش رو خراب می‌کردن رفع شدن.

## چیزهایی که هنوز باید خودت تست کنی (اینجا امکان اجرای FiveM واقعی نیست)
- UI کامل خودِ `esx_inventoryhud` (فایل‌های `html/ui.html` و JS/CSS جداگونه‌ش) عمداً حذف شد چون `esx_inventory` رابط اصلیه و اجرای هر دو همزمان تداخل ایجاد می‌کرد. فقط منطق سرور + رویدادهای کلید (`getOwnerVehicle`/`getOwnerHouse`) نگه داشته شد. اگه جایی مستقیم داشت اون UI جدا رو صدا میزد (مثلاً یه export یا event خاص)، بگو تا چک کنم.
- بعد از نصب، حتماً لاگ کنسول سرور رو موقع استارت چک کن — اگه `callback_bridge.lua` نتونه به essentialmode وصل بشه، خطاش پرینت می‌شه.

## نسخه ۱.۱.۰ (نسخه‌ی نهایی) — تغییرات

### سریال اسلحه در توضیحات
- `essentialmode` از قبل برای هر اسلحه سریال می‌ساخت (`LAW-xxxxx-xxxx` / `DOJ-…` / `GANG-…`) ولی به UI نمی‌رسید. الان `getPlayerInventory2323` سریال رو می‌فرسته.
- موس رو روی هر اسلحه ببری، کارت سریال طلایی/مشکی نشون داده میشه: برچسب رنگی نوع سریال (LAW طلایی، DOJ آبی، GANG قرمز)، شماره‌ی سریال، منبع اسلحه، تعداد تیر و وزن. اسلحه‌ی بدون سریال «UNREGISTERED» قرمز نشون میده.
- اسلحه‌هایی که از اسلحه‌خونه‌ی جاب گرفته میشن سریال `DOJ-` می‌گیرن (و توی لاگ دیسکورد هم سریال ثبت میشه).

### باگ وزن اسلحه
وزن اسلحه × تعداد تیر حساب می‌شد (۲kg × ۱۵۴ تیر = «308kg» و کل «3254.5/90»). الان هر اسلحه یک‌بار وزن داره، هم روی کارت و هم توی جمع کل.

### UI
- بخش Cash Amount / Bank Amount از سمت راست اینونتوری حذف شد (`nui/index.html` + `nui/app.js`).

### امنیت (اکسپلویت‌های بسته‌شده)
- `Parzival:GetJobWeapon`: قبلاً هر بازیکنی می‌تونست هر اسلحه‌ای با ۲۵۰ تیر بگیره. الان اسلحه باید توی لیست مجاز همون بازیکن باشه (همون لیستی که منو نشون میده).
- `Parzival:PutJobWeapon`: متغیر تعریف‌نشده‌ی `src` رفع شد.
- `esx_inventoryhud:getPlayerInventory` / `getPlayerInventory1`: قبلاً هر `target` رو قبول می‌کردن. الان فقط خودِ بازیکن، کسی که کنارشه (تا ۶ متر، برای بازرسی) یا ادمین (`permission_level > 1`).
- `getPlayerInventory1`: دیگه کلید و اکسسوری رو داخل اینونتوری زنده‌ی بازیکن `table.insert` نمی‌کنه (روی کپی کار می‌کنه).
- `esx_inventoryhud:updateKey`: ورودی‌ها اعتبارسنجی میشن (target معتبر، نوع کلید، فاصله ≤ ۸ متر) و از `xPlayer.identifier` استفاده می‌کنه. نوتیف‌های Thai/pNotify با `esx:showNotification` عوض شدن.
- `print`های دیباگ حذف شدن.

### هنوز باقی‌مونده
انتقال اسلحه به ترانک/خونه/استش گنگ و Drop، فقط با اسم اسلحه کار می‌کنه (سریال همراهش نمی‌ره). برای اینکه سریال کامل همراه اسلحه بمونه باید `essentialmode` (`esx:removeInventoryItem` و pickup) و اسکریپت‌های مقصد هم تغییر کنن.

## نسخه ۱.۲.۰ — صندوق عقب با ox_target + داشبورد

### صندوق عقب با ox_target
- روی صندوق عقب هر ماشین که نگاه کنی (بیرون از ماشین)، گزینه‌ی «باز کردن صندوق عقب» میاد. لازم نیست دقیقاً پشت ماشین بایستی؛ فقط باید کنار صندوق (حداکثر ~۴.۵ متر) باشی.
- کد توی `client/vehicle_target.lua` است. لیبل و آیکن بالای همون فایل قابل تغییره.
- `openmenuvehicle(entity)` و اکسپورت `openTrunk(entity)` الان خودِ ماشین رو می‌گیرن (قبلاً پارامتر نادیده گرفته میشد و فقط raycast جلوی بازیکن کار می‌کرد). کلید Alt با raycast قدیمی هنوز به‌عنوان جایگزین کار می‌کنه (برای ماشین‌هایی که استخوان `boot` ندارن).
- اگه توی `Config.vehicleMenu` گزینه‌ی صندوق داری: `exports['Unique_inventory']:openTrunk(_)` (اسم ریسورس `Unique_inventory` است، نه `inventory-hud`).

### داشبورد (Glovebox)
- توی ماشین (راننده یا سرنشین) کلید اینونتوری (F2) رو بزنی، داشبورد همون ماشین کنار جیب‌ها باز میشه. بیرون از ماشین، همون اینونتوری عادی.
- ظرفیت: `TrunkConfig.GloveboxLimit` (پیش‌فرض ۵۰۰۰ گرم). کلاس‌های بدون داشبورد (موتور، دوچرخه، قطار): `TrunkConfig.GloveboxNoClass`.
- ظرفیت داشبورد سمت **سرور** هم اعمال میشه، پس با تغییر مقدار از کلاینت نمیشه دورش زد.
- داشبورد با کلید `GLOVE:<پلاک>` توی همون جدول `trunk_inventory` ذخیره میشه. **حتماً `install.sql` رو یک‌بار اجرا کن** (ستون `plate` باید از `varchar(8)` بزرگ‌تر بشه).
- اکسپورت `exports['Unique_inventory']:openGlovebox()` هم هست.

### بقیه
- کلید F2 حالا با `IsControlJustPressed` کار می‌کنه (قبلاً تا وقتی نگه‌داشته بودی هر فریم رویداد می‌فرستاد).
- نوتیف‌های ترانک (فضای کافی نیست، مقدار نامعتبر، ...) که با pNotify می‌رفتن (نصب نیست، پس هیچ‌وقت نشون داده نمی‌شدن) الان با `esx:showNotification` نشون داده میشن.
- ظرفیت ترانک/داشبورد: پارامتر `max` که کلاینت می‌فرسته برای داشبورد نادیده گرفته میشه.

## نسخه ۱.۳.۰ — روی آخرین گیت

### ظاهر اینونتوری (بیرون از کادر)
- `css.css`: مقدارهای `--ui-shift-x` (`-7vw`) و `--chest-title-x` (`-3vw`) کل اینونتوری رو زیادی به چپ هل می‌دادن و ستون اول صندوق/داشبورد ~۲vw بیرون از صفحه می‌افتاد. الان همه `-4vw` هستن (گرید چپ در `1vw`، پنل راست در `96vw`؛ روی ۱۹۲۰×۱۰۸۰، ۱۳۶۶×۷۶۸، ۱۶۰۰×۹۰۰، ۱۲۸۰×۱۰۲۴ و ۲۵۶۰×۱۰۸۰ اندازه‌گیری شد).
- `.chest-title-menu` دیگه `transform` نداره: transform اون رو containing block بچه‌های absolute می‌کرد و خط زیر عنوان ~۳.۵vw پایین می‌افتاد و روی گرید خط می‌کشید.
- `app.js`: خط کنار عنوان (`fitChestTitleLine`) همیشه بعد از متن عنوان شروع میشه؛ عنوان بلند «GLOVEBOX | پلاک» دیگه خط‌خورده نمیشه.

### پیکاپ / دراپ (essentialmode)
- **ارور کنسول `main.lua:1221`** (`attempt to index a nil value (global 'sourceXPlayer')`): توی `esx:onPickup` وقتی بازیکن همون اسلحه رو داشت. ارور هندلر رو نصفه می‌کرد.
- **آیتم روی زمین می‌موند:** کلاینت با زدن E مقدار `inRange=true` می‌ذاره و فقط `esx:pickupUpdate` ریستش می‌کنه. الان سرور موقع رد کردن اون رو می‌فرسته، و کلاینت هم بعد از ۳ ثانیه خودش ریست می‌کنه.
- **سریال موقع Drop/Pickup حفظ میشه** (قبلاً `addWeapon` هر بار سریال جدید می‌ساخت).
- پیکاپ روی سرور محل قرارگیری رو نگه می‌داره؛ بازیکن باید تا ۶ متر نزدیکش باشه.
- قبل از دادن اسلحه، پیکاپ از روی زمین برداشته میشه (پیکاپ دوبار قابل برداشتن نیست).
- ⚠️ قانون قبلی حفظ شده: اگه از همون نوع اسلحه داری نمی‌تونی یکی دیگه برداری؛ اسلحه سر جاش می‌مونه و پیام میاد.

### صندوق عقب / داشبورد (سمت سرور)
- **دوپ آیتم بسته شد:** `putItem` اول تعداد رو توی استور زنده زیاد می‌کرد و بعد ظرفیت رو چک می‌کرد. پر بود؟ پیام «فضا نیست» می‌اومد ولی آیتم توی استور مونده بود و از جیب هم کم نشده بود. الان اول ظرفیت چک میشه (آیتم، اسلحه و پول کثیف).
- **چک فاصله سمت سرور** (`TrunkConfig.ServerProximityCheck`): برای خوندن/گذاشتن/برداشتن باید تا ۱۰ متر (صندوق) یا ۶ متر (داشبورد) از ماشینی با همون پلاک باشی. نیاز به OneSync دارد؛ اگه نبود چک رد میشه و یه هشدار توی کنسول میاد.
- **سریال اسلحه از صندوق/داشبورد رد میشه** (با همون سریال برمی‌گرده).
- برداشتن اسلحه‌ای که توی صندوق نیست دیگه اسکریپت ارور نمی‌ده.
- ظرفیت داشبورد ۱۰ کیلو (`WEAPON_PISTOL` تنهایی ۵ کیلوئه).

## نسخه ۱.۴.۰ — چند اسلحه‌ی هم‌نوع توی جیب

- **کانفیگ:** `Config.MaxSameWeapon` در `essentialmode/config.lua` (پیش‌فرض `3`). هر نسخه سریال خودش رو داره و توی اینونتوری جدا نشون داده میشه. `1` = قانون قدیمی «یک اسلحه از هر نوع».
- **Pickup:** تا سقف کانفیگ می‌تونی از همون اسلحه برداری؛ بعد از سقف، اسلحه روی زمین می‌مونه و پیام میاد.
- **Drop و گذاشتن توی صندوق/داشبورد دقیقاً همون نسخه‌ای که انتخاب کردی** (UI سریال رو می‌فرسته). قبلاً همیشه «اولین اسلحه‌ی هم‌اسم» برداشته میشد.
- **Give:** اسلحه با سریال خودش به گیرنده میره و گیرنده اگه کمتر از سقف داشته باشه می‌تونه بگیره.
- **رفع دیسینک GTA:** GTA فقط «اسلحه هست/نیست» رو می‌شناسه. وقتی یکی از چند نسخه رو بدی/دراپ کنی، اسلحه از دست پد برداشته نمیشه و فقط سهم مهمات اون نسخه کم میشه (`esx:removeWeapon` پارامتر `keep`). فقط آخرین نسخه کامل حذف میشه.
- **رفع باگ داشبورد:** بعد از گذاشتن/برداشتن آیتم، اینونتوری با `openmenuvehicle()` (مخصوص صندوق) دوباره باز میشد که داخل ماشین کاری نمی‌کرد و داشبورد بسته می‌شد. الان `ReopenSecondInventory()` داشبورد رو دوباره باز می‌کنه.
- اسلحه‌خونه‌ی جاب (`Parzival:GetJobWeapon`) عمداً هنوز اجازه نمی‌ده از همون اسلحه‌ی آرموری دوتا برداری.
- ⚠️ مهمات: GTA برای هر نوع مهمات یه استخر مشترک داره، پس چند نسخه‌ی هم‌نوع یه استخر مهمات دارن.

## نسخه ۱.۵.۰

- **`NaNkg` روی آیتم‌های صندوق/داشبورد:** سرور برای آیتم‌های ترانک `peso` (وزن یک واحد به کیلو) نمی‌فرستاد و UI مقدار `peso * count` رو حساب می‌کرد (`undefined * 1 = NaN`). الان `getInventoryV` فیلد `peso` رو می‌فرسته (اسلحه = یک بار وزن خودش، نه × تعداد تیر) و JS هم دیگه هیچ‌وقت NaN نشون نمی‌ده.
- **حلقه‌ی «Second Space» به کیلو:** وزن‌های ترانک به گرم ذخیره میشن ولی کارت‌ها و متن اطلاعات به کیلو بودن؛ حلقه هم به کیلو نشون داده میشه (`1000.0/10000.0` → `1.0/10.0`).
- **ارور `hud_keys.lua:1292`** (`bad argument #1 to 'for iterator' (table expected, got number)`): سرور `esx_inventoryhud:refreshTrunkInventory` رو با ۴ آرگومان `(data, blackMoney, items, weapons)` می‌فرسته ولی هندلر کلاینت ۳ تا می‌گرفت؛ پس `inventory` عدد `blackMoney` می‌شد. بعد از هر گذاشتن/برداشتن ارور می‌داد. هندلر اصلاح شد و ورودی‌ها رو چک می‌کنه.
- **کلید Left-Alt دیگه صندوق رو باز نمی‌کنه:** هندلر `onKeyUP` (raycast جلوی بازیکن) حذف شد. صندوق فقط با ox_target باز میشه و داشبورد با کلید اینونتوری داخل ماشین.
- **برداشتن اسلحه از صندوق/داشبورد دقیقاً همون نسخه‌ای که انتخاب کردی** (با سریال) و کارت سریال روی اسلحه‌های داخل صندوق هم با هاور نشون داده میشه.

## نسخه ۱.۵.۱ — گزینه‌ی صندوق ox_target دیده نمی‌شد

- **علت:** گزینه با `bones = { 'boot' }` ثبت شده بود. ox_target گزینه‌ی bone رو فقط وقتی نشون میده که نقطه‌ی برخورد کراس‌هیر ≤ ~۱ واحد از استخوان باشه، و علاوه بر اون بازیکن باید ≤ `distance` (۲ متر) از نقطه‌ی برخورد باشه. یعنی فقط وقتی دقیقاً پشت ماشین وایستاده بودی و دقیقاً به صندوق نشونه می‌گرفتی؛ روی درها فقط «Toggle door» میومد.
- **الان:** `bones` حذف شد. گزینه روی هر جای ماشین میاد و `canInteract` فاصله‌ی **خودِ بازیکن تا صندوق** رو چک می‌کنه (`TrunkConfig.TrunkReach`، پیش‌فرض ۴ متر).
- **ماشین‌هایی که صندوقشون جلوئه** (موتور عقب/وسط): اسم مدلشون رو (lowercase) توی `TrunkConfig.FrontTrunkModels` بذار تا از استخوان `bonnet` استفاده کنه.
- اگه ماشین استخوان `boot` نداشته باشه، انتهای عقب مدل به‌عنوان صندوق حساب میشه.
- `GetTrunkPosition(vehicle)` یک تابع مشترک بین ox_target و `openmenuvehicle` است.

## نسخه ۱.۵.۲ — گزینه‌ی صندوق از هر جای ماشین

- تا نسخه‌ی قبل، برای دیدن گزینه هم باید نزدیک خود صندوق می‌ایستادی (`TrunkConfig.TrunkReach`) هم نشونه می‌رفتی. الان کافیه نزدیک **ماشین** باشی (هر بخشش: در، سقف، کاپوت، هر جا) و از همون فاصله (`TrunkConfig.TrunkReach`، پیش‌فرض ۴ متر) گزینه میاد.
- `GetTrunkPosition` و `TrunkConfig.FrontTrunkModels` جایی نرفتن؛ فقط برای موقعیت واقعی صندوق (انیمیشن باز شدن و محل فایل‌های ذخیره) استفاده میشن، نه برای تصمیم اینکه گزینه نشون داده بشه یا نه.
