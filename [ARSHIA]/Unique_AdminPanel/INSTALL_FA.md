# نصب - سیستم تیکت + بسته‌شدن خودکار ریپورت

## فایل‌های تازه (فقط کپی کن، جایگزین نمی‌کنن)
کپی کن داخل `[ARSHIA]/Unique_AdminPanel/`:
- `shared/ticket_config.lua`
- `server/ticket_main.lua`
- `server/report_autoclose.lua`
- `client/ticket_client.lua`
- `html/ticket/` (کل پوشه: index.html + css/style.css + js/app.js)
- `sql/tickets.sql`
- `sql/report_autoclose.sql`

## فایل‌هایی که باید جایگزین (Replace) بشن
این ۳ تا از قبل تو ریسورس شما وجود دارن؛ نسخه‌ی داخل این پکیج = نسخه‌ی خودتون + اضافات تیکت. جایگزینشون کن:
- `fxmanifest.lua`
- `html/index.html`
- `client/menuv_ui.lua`

اگه از آخرین باری که این رو گرفتی خودتون این ۳ فایل رو دستی تغییر داده باشین، دیف رو خودتون چک کنین چون Replace کامل میکنه رو دیفشون.

## دیتابیس
یک‌بار این دوتا رو روی دیتابیس essentialmode اجرا کن:
```
mysql -u USER -p DB_NAME < sql/tickets.sql
mysql -u USER -p DB_NAME < sql/report_autoclose.sql
```

## چی اضافه شد

### ۱) سیستم تیکت
- `/ticket` برای بازیکن عادی (تیکت‌های خودش)
- `/atickets` برای ادمین (پنل کامل مدیریت) - یک دکمه «🎫 Tickets» هم به منوی F4 اضافه شد
- تیکت میتونه از صفر ساخته بشه یا از روی یک گزارش بازِ موجود («ساخت تیکت از یک گزارش باز» تو پنل ادمین) - بدون اینکه هیچ فایلی از سیستم ریپورت خودتون تغییر کنه، فقط از exportـی که خودش قبلاً منتشر می‌کنه می‌خونه.
- تو هر تیکت: افزودن/حذف بازیکن (جستجو با نام یا آیدی، آنلاین یا آفلاین)، افزودن/حذف ادمین مسئول (از بین ادمین‌های آنلاین)، چت تِرد، تغییر وضعیت (باز / درحال‌بررسی / بسته‌شده).
- آپدیت‌ها لایو پوش میشن (`Unique_Ticket:push`) به هر کسی که تو اون لحظه تیکت رو بازه - نیازی به رفرش دستی نیست.
- ظاهرش هم‌رنگ پنل ریپورتِ خودتونه (همون پالت تیره + کهربایی) تا حس یک پنل واحد بده.

### به‌روزرسانی ظاهر و رفتار پنل تیکت
- ظاهرِ کامل بازطراحی شد: یک فریمِ «تبلت» وسط صفحه (نه تمام‌صفحه) با بزلِ گرد، سایه، نوارِ ساعت زنده و دکمه‌ی بستن اختصاصی - نه فقط یک پنجره‌ی ساده.
- شماره‌ی هر تیکت همه‌جا یکدست و پدینگ‌شده نمایش داده میشه (مثلاً `#0042`).
- اولویت (پایین/متوسط/بالا) هم موقع ساخت تیکت قابل انتخابه، هم بعداً از پنل ادمین قابل تغییره؛ رنگش رو کارت‌های لیست و هدر تیکت مشخصه.
- دکمه‌ی «🔗 گزارش مبدأ» روی تیکت‌هایی که از یک گزارش ساخته شدن ظاهر میشه و جزئیات همون گزارش (حتی اگه الان بسته/آرشیو شده باشه) رو تو یک مودال نشون میده - از `Unique_Ticket:getLinkedReport` که مستقیم از جدول `reports` میخونه، نه از exportـی که فقط ریپورت‌های باز رو میده.
- **تیکت‌ها هیچ‌وقت خودشون بسته نمیشن.** برخلاف سیستم ریپورت (که بالا توضیح داده شده و خودکار می‌بنده)، تو `server/ticket_main.lua` هیچ تایمر/ترد پس‌زمینه‌ای وجود نداره که وضعیت رو دست بزنه؛ تنها راهِ بسته‌شدن، فراخوانیِ صریحِ `Unique_Ticket:setStatus(..., 'closed')` توسط یک ادمینه. سمتِ کلاینت هم قبل از بستن، یک مودالِ تأیید («⚠️ بستن تیکت») نشون داده میشه تا با یک کلیکِ اشتباه بسته نشه. بعد از بسته‌شدن، اسمِ ادمینی که بسته و زمانش بالای صفحه‌ی تیکت نمایش داده میشه.

### ۲) بسته‌شدن خودکار ریپورت بعد از ۳۰ دقیقه بدون پیگیری
`server/report_autoclose.lua` (فایل جدید و مجزا، هیچ فایلی از سیستم ریپورتِ خودتون رو ادیت نمیکنه):
- هر ۶۰ ثانیه چک میکنه؛ هر ریپورتی که ۳۰ دقیقه (`Config_Server.autoCloseMinutes`) تو وضعیت `pending` مونده و هیچ ادمینی قبولش نکرده رو خودش می‌بنده.
- به همه‌ی ادمین‌های آنلاین نوتیف عمومی میده که ریپورت #N خودکار بسته شد.
- یک نوتیفِ جداگانه و واضح‌تر هم فقط برای رنک ≥ ۳ (`Config_Server.autoCloseNotifyLevel`، قابل تغییر) میفرسته تا رنک‌بالاها پیگیری کنن چرا هیچ ادمینی جواب نداده.
- یک ردیفِ دائمی تو جدولِ `report_autoclose_log` ثبت میکنه (حتی اگه موقع اتفاق هیچ ادمینی آنلاین نبوده) + اگه وبهوک دیسکورد (`Config_Server.Discord.webhook`) روشن باشه، اونجا هم لاگ میره.
- تنظیمات قابل تغییرن (میتونی تو `server/report_autoclose.lua` مقادیر پیش‌فرض رو عوض کنی):
  - `Config_Server.autoCloseMinutes = 30`
  - `Config_Server.autoCloseCheckSeconds = 60`
  - `Config_Server.autoCloseNotifyLevel = 3`
