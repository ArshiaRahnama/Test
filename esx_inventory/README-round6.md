# راند ۶ — اسلحه‌ی غول‌پیکر وسط صفحه + هات‌بار

روی `[BASE]/esx_inventory` کپی کن و `restart esx_inventory` بزن.

---

## باگ اصلی: یک خط CSS

آن پیستول غول‌پیکر روی ped، آن کادر سبز دور کل ستون وسط، و اینکه
«گان‌ها را نمی‌شود توی هات‌بار گذاشت» — **هر سه یک باگ بودند**.

راند ۴ برای درست کردن مشکل «اسم روی عکس»، `.item` را کرد
`position:absolute; inset:0`. برای سلول‌های گرید درست است، چون
`.item-info` خودش `position:relative` دارد. ولی سلول **هات‌بار**
(`.middle-slot-box`) هیچ `position` ای نداشت — پس یک المان absolute
داخلش نسبت به نزدیک‌ترین جد موقعیت‌دار حساب شد، یعنی `.center-part` که
`position:absolute` است.

نتیجه: به‌محض اینکه یک اسلحه به اسلات هات‌بار بایند می‌شد، آیکونش کشیده
می‌شد روی **کل ستون وسط**:

- پیستول غول‌پیکر روی ped
- کادر نورانی دور کل پنل وسط ← این بوردر/گلوی خودِ آیتم بود
- لیبل `Pistol #LAW-11279-0001` آویزان مانده در پایین صفحه
- و مهم‌تر از همه: یک المان نامرئی به اندازه‌ی کل پنل، **روی**
  USE / GIVE / RENAME / DELETE / DROP و چهار اسلات دیگر هات‌بار، که همه‌ی
  کلیک‌ها و همه‌ی drop‌ها را می‌بلعید.

برای همین «گان تو هات‌بار نمی‌رفت»: گانِ اول همه‌ی بقیه را بلاک می‌کرد.

فقط یک containing block کم بود:

```css
.middle-slot-box { position: relative; }
```

## باگ دوم: هات‌بار اسلات اشتباهی را پاک می‌کرد

توی `PutIntoFast`، فیلد `data.item.slot` حالا **دو معنی متفاوت** دارد:

- برای آیتمی که از هات‌بار درگ شده = ایندکس هات‌بار (۱ تا ۵)
- برای آیتمی که از اینونتوری درگ شده = خانه‌ی گرید (۱ تا ۵۰) — این را
  لایه‌ی slot در راند ۳ اضافه کرد

کد هر دو را یکسان می‌دید و کورکورانه پاک می‌کرد. یعنی: آیتمی که در خانه‌ی
گرید ۳ بود را بکش روی اسلات ۱ هات‌بار → هرچه به اسلات ۳ هات‌بار بایند بود
بی‌صدا پاک می‌شد. حالا فقط وقتی درگ واقعاً از هات‌بار شروع شده باشد
(`data.from == 'fast'`) پاک می‌شود.

ضمناً وقتی آیتم در `Config.BL_SlotInv` بود، تابع بدون صدا زدن `cb()` تمام
می‌شد و کال‌بک NUI معلق می‌ماند. حالا نوتیف می‌دهد و درست می‌بندد.

## پنل زمین: هدر

نوار خاکستری خالیِ بالای پنل راست (که برای صندوق نوار وزن است) برای پنل
زمین بی‌معنی بود و روی لیست شناور می‌شد. حالا مخفی می‌شود و عنوان
«روی زمین» دقیقاً همان‌جایی می‌نشیند که صندوق پلاکش را نشان می‌دهد، تا هر
دو پنل یک‌جور خوانده شوند.

## ظاهر

- هات‌بار: بج کلید ۱ تا ۵ دیگر با مارجین ثابت شناور نیست، گوشه‌ی سلول پین شده
- هاور روی اسلات‌های هات‌بار و دکمه‌های وسط (بالا آمدن + گلو)
- کلاس `hoverControl` (وقتی آیتم را روی USE/GIVE/… نگه می‌داری) حالا
  واقعاً دیده می‌شود — قبلاً استایلش خالی بود
- فریم پنل‌ها، زیرخط دسته‌بندی فعال، فوکوس سرچ

**عمداً `backdrop-filter` نگذاشتم**: بازی خودش پشت این UI را با
`TriggerScreenblurFadeIn` بلور می‌کند. یک بلور دوم روی GPU فقط فریم
می‌خورد بدون اینکه چیز جدیدی روی صفحه بیاورد.

## یک نکته درباره‌ی لیست چپ

در اسکرین‌شات فقط ۴ آیتم دیده می‌شود، ولی وزن ۲۱۰.۵ است. این باگ نیست:
اسلحه‌ها و لباس‌ها زیر جداکننده‌ی **Equipment** پایین‌تر لیست‌اند و باید
اسکرول کنی. دلیلش هم از راند ۳ همین بوده: آن‌ها در `loadout` و
`lc_clothes` ذخیره می‌شوند که اصلاً مفهوم «خانه‌ی گرید» ندارند، پس
نمی‌شود برایشان جای ثابت در گرید ساخت که بعد از ریلاگ هم بماند.

اگر می‌خواهی اسلحه‌ها **بالای** لیست بیایند نه پایینش، بگو — یک خط
ترتیب باندها است.
